Weightlifting Fatigue Detector

Ava Sokolosky
COMPSCI 528: Mobile and Ubiquitous Computing, UMass Amherst, Spring 2026

I built a wrist-worn system that watches a set in real time and labels each rep as Normal or Near Failure, which I defined as the last 1 to 3 reps before the lifter cannot complete another full rep. On bicep curls it reached 84% test accuracy and caught 87% of near-failure reps.

Why

Muscle growth, or hypertrophy, depends on how hard a set is. Research suggests that in order to optimize hypertrophy, it is best to train in a 6-15 rep range with 0-5 Reps in Reserve (RIR). However, training near concentric muscular failure is hard to determine. A lot of weightlifters don’t push themselves hard enough and are left confused and frustrated on why they are not making any progress. Instead of relying only on how a set “feels,” a wearable system could detect motion-based signs of fatigue to help determine if someone is training hard enough.

Data

I recorded 20 sets of bicep curls and 10 sets of lateral raises, each taken to failure, from two lifters. Every set is its own CSV with a timestamp, acceleration on three axes (ax_g, ay_g, az_g), and angular velocity on three axes (gx_dps, gy_dps, gz_dps).

Finding the reps

Bicep curls and lateral raises look very different in the data, so each one needed its own approach.

Bicep curls show a clean rise and fall in vertical acceleration (ay_g). I used a 3 Hz Butterworth low-pass filter and prominence-based peak detection, and threw out anything shorter than 1 second or with less than 0.8 g of range.

Lateral raises are messier. The lateral acceleration (az_g) has several small bumps per rep, so I merged sub-peaks below the threshold into one rep. For these I used a 2 to 2.5 Hz filter and a 1.5 second minimum duration.

What the model looks at

For each rep I computed time-domain stats (mean, standard deviation, min, max, range, RMS, energy), frequency-domain features (dominant frequency, spectral energy and entropy, low/mid/high band energy), and jerk and magnitude features.

The features that mattered most were the baseline-relative ones. Each rep's jerk and frequency features are compared to the average of the first few reps in the set, so the model can see how a rep has changed for that person instead of using absolute values that can vary a lot between people.

Running it live

The real-time version waits for a full rep to be detected, uses the first 3 reps of the set as the baseline, and then outputs a probability that each new rep is near failure. I set the cutoff low, at 0.3. Missing a real near-failure rep is worse than warning someone a little early, so I traded some precision for recall.

Bicep curls were the most reliable. Lateral raises had half as much data, and the model is probably overfitting to my rep patterns.

What didn't work well

  • Not enough variety in the data. The model was good at my slow, controlled reps, but not everyone lifts that way.
  • Pauses between reps. The live segmenter sometimes missed reps when there was a pause.
  • One threshold for everyone. The cutoff that worked for my sets didn't work as well for the other lifter's. An adaptive threshold that starts higher and drops later in the set would probably help.

Next steps

  • Collect data from more lifters and more exercises, like presses and rows.
  • Try other models, including SVMs and LSTMs.
  • Alert the lifter mid-set with a screen or haptics.
  • Suggest weight changes after a workout: go up if user completes target number of reps without nearing failure, and go down if user hits failure too early in the set.
